# LoanBreaker

LoanBreaker is a small, open Streamlit app that helps borrowers understand where an education loan stands and how an extra payment may change the payoff timeline. V1 has no login, no bank connection, and no cloud database. Loan and payment data lives only in the active Streamlit session unless the user exports CSV files.

## What the MVP includes

- **My Loan:** loan setup, current lender balance, interest-rate history, dashboard metrics, and an estimated balance trend.
- **Add Payment:** payment date, optional lender credited date, amount, type, edit/delete, and CSV import/export.
- **What If:** a one-time extra-payment scenario showing the estimated new balance, payoff date, months saved, interest saved, and a comparison chart.
- A UI-independent Python engine with daily interest accrual, payment allocation, variable historical rates, part-interest modeling, and payoff projections.
- Automated tests, including an anonymized part-interest case where unpaid interest causes the balance to increase.

## Run locally

Python 3.11 or newer is recommended.

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
streamlit run app.py
```

Then open the local address printed by Streamlit, usually `http://localhost:8501`.

## Run the tests

```bash
pytest -q
```

## Calculation approach

LoanBreaker stores only source facts in session state: setup values, rate changes, and payments. Calculated values are regenerated by `loanbreaker/engine.py`.

1. Interest accrues daily on the total unpaid balance using `balance × annual rate ÷ day-count basis`.
2. The engine uses the most recent rate effective on each date.
3. A payment is applied on its lender credited date when supplied; otherwise its payment date is used.
4. Payments cover unpaid interest first, then principal.
5. If a part-interest payment is below interest accrued, the remainder stays unpaid and the outstanding balance can rise.
6. Historical results are estimates from entered events. The lender-reported current balance is kept as the authoritative starting point for future payoff and extra-payment scenarios.
7. Future projections hold the current rate and EMI constant. They do not predict future rate changes.

### Part-interest validation

The private lender schedules supplied during product discovery were used only to identify representative behavior. They are not included in this repository. The committed test fixture uses generic, altered values: a large education-loan balance, a double-digit rate, and a small monthly part-interest payment. The test verifies that the payment is consumed by interest, principal does not reduce, and the total balance increases when interest remains unpaid.

## CSV formats

Payments:

```csv
payment_id,payment_date,credited_date,amount,payment_type
example-1,2026-01-05,2026-01-06,25000.00,EMI
```

Interest-rate history:

```csv
effective_date,annual_rate
2025-01-01,11.2500
2025-08-01,11.7500
```

Use fictional examples in source control. Keep real exports and lender documents private.

## Privacy and scope

- No authentication, Supabase, telemetry, lender integration, or background storage in V1.
- `.gitignore` excludes PDFs, spreadsheets, local data, exports, secrets, and environment files.
- Closing or resetting the Streamlit session can remove unsaved data, so export CSV backups when needed.

## Important disclaimer

LoanBreaker provides **estimates for educational planning only**. It is not a lender statement, financial advice, or a promise of savings. Lenders may use different day-count conventions, posting dates, compounding/capitalization rules, rounding, fees, prepayment allocation, holidays, and contract terms. Always compare results with the latest lender statement and confirm material repayment decisions with the lender or a qualified financial professional.
